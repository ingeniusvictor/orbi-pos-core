# OC-23 — Owner Pilot Summary & Print Pack

## Goal

Produce one owner-readable summary of the ORBI pilot that can be printed or saved as PDF directly from the browser.

## Route

~~~text
/piloto/resumen
~~~

The owner pilot hub links to this page through **Resumen imprimible** / **Resumen / PDF**.

## Data sources

The summary is derived from existing pilot state:

- master catalog;
- OC-19 field discovery;
- OC-18 modernization proposal;
- OC-21 readiness model.

It does not create a second independent source of truth.

## Included sections

1. confirmed current-shop facts;
2. target ORBI architecture;
3. software/demo readiness;
4. field/production validation;
5. cost-benefit state;
6. main blockers / next steps;
7. pilot conclusion.

## Economic integrity

The report reuses the same OC-18 calculation rules.

If required inputs are incomplete:

~~~text
Comparación económica pendiente
Sin conclusión económica todavía
~~~

No monthly savings, annual savings or payback claim is displayed.

If the supplied assumptions indicate a higher proposed cost, the report says so instead of forcing a positive conclusion.

## Fiscal boundary

The current SUNMI/Inputsoft/SII issue is described only as a reported incident under investigation unless the discovery has enough explicit answers.

Even a completed discovery checklist is not represented as tax approval.

The report continues to state that the fiscal path must be validated before any replacement/migration decision.

## Scale boundary

The four DIGI RM-60 units remain part of the proposed architecture.

Automatic write integration remains outside production readiness until:

- the real principal workflow is observed;
- secondary propagation is observed;
- protocol/software path is confirmed;
- a recoverable backup exists.

## Point boundary

The software demo can show the mock Point flow.

A real Point Smart 2 remains pending until physical acquisition/association and production identifiers/mode exist.

## Print / PDF

The page exposes:

~~~text
Imprimir / Guardar PDF
~~~

which calls the browser print dialog.

The print stylesheet:

- hides action buttons;
- preserves status colors where the browser supports print backgrounds;
- removes application shadows;
- keeps major blocks together where possible;
- targets A4 output.

No PDF file is generated by the server.

## Purpose

This page is designed as a meeting handout / leave-behind.

It should make sense to an owner without requiring access to the technical admin screens.
