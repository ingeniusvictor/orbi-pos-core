# OC-13 — Payment Core & Mercado Pago Point Provider

## Goal

Let ORBI POS own the sale workflow while a payment provider owns the actual card transaction.

The browser never receives a Mercado Pago Access Token.

## Provider model

The ORBI sync server now exposes a payment-provider boundary:

~~~text
ORBI POS browser
      |
      v
ORBI payment API
      |
      +---- MockPointProvider
      |
      +---- MercadoPagoPointProvider
~~~

The default provider is `mock`.

A real provider is enabled only when the ORBI server is explicitly configured with environment variables.

## Current Mercado Pago Orders contract

The production adapter follows the current Point Orders API contract:

- POST `https://api.mercadopago.com/v1/orders`
- GET `https://api.mercadopago.com/v1/orders/{order_id}`
- POST `https://api.mercadopago.com/v1/orders/{order_id}/cancel`
- `Authorization: Bearer <Access Token>`
- `X-Idempotency-Key`
- `type=point`
- unique `external_reference`
- integer CLP amount
- `config.point.terminal_id`

ORBI uses a ten-minute expiration for created payment orders.

Official references:

- https://www.mercadopago.cl/developers/es/docs/mp-point-v2/payment-processing
- https://www.mercadopago.cl/developers/es/reference/in-person-payments/point/orders/create-order/post
- https://www.mercadopago.cl/developers/es/reference/in-person-payments/point/orders/get-order/get
- https://www.mercadopago.cl/developers/es/reference/in-person-payments/point/orders/cancel-order/post

## Idempotency

Every ORBI payment attempt has two identifiers:

- `clientRequestId` — generated by the POS and reused if the browser retries the same creation request;
- `idempotencyKey` — generated on the ORBI backend and sent to Mercado Pago.

If the browser repeats the same `clientRequestId`, ORBI returns the same local payment order rather than creating a second provider payment.

## Payment state model

ORBI follows Point Orders states:

~~~text
created
at_terminal
processed
failed
canceled
expired
refunded
~~~

Only `processed` means the payment was successfully confirmed for the sale workflow.

## Storage

Payment attempts are stored separately from the product catalog:

~~~text
data/stores/<store>/payments.json
~~~

The payment audit is retained even when a payment fails or is canceled.

## Security boundary

Do not place `MERCADO_PAGO_ACCESS_TOKEN` in Vite/browser variables.

The access token belongs only in the Node ORBI server environment.

The repository contains `.env.example` placeholders only. No real credentials or real terminal identifiers are committed.
